# 聊天室

> 三栏即时通讯布局 + LaTeX 公式的**注册审核制**网页聊天室：进入密码保护、三级管理员体系、
> 私聊 / 自建群 / 公屏大厅、图片视频预览、Markdown 与 `$...$` LaTeX 公式。
> **纯前端零依赖，双击 `index.html` 就能用，可直接部署到 GitHub Pages 免费版。**

---

## 〇、站点地图

本项目是一个**多页面站点**，共四个板块：

| 板块 | 路径 | 网址（仓库名 Chat） |
| --- | --- | --- |
| **主页** | `index.html` | `/Chat/` |
| **聊天室** | `chat/index.html` | `/Chat/chat/` |
| **贴吧** | `tieba/index.html` | `/Chat/tieba/` |
| **使用手册** | `docs/index.html` | `/Chat/docs/` |

手册分六页：手册首页、新手入门、Markdown 与公式、权限与命令、管理员手册、部署与数据。
全部页面共用 `assets/site.css` 与 `assets/site.js`（顶部导航 + 深色模式）。

### 先判断：要不要配数据库

| 你想怎么用 | 要不要配后端 |
| --- | --- |
| 自己用 / 同一台电脑多标签自测 | **不用** |
| 部署给几个人用，不要求跨设备同步 | **不用** |
| 需要跨设备、关掉浏览器数据还在 | 需要（Supabase） |

> 聊天室与贴吧的后端访问层、建库脚本都已备好（`js/sb.js`、`supabase/*.sql`），
> 但默认走本地存储。等你网络能顺畅打开 Supabase 后台时再接上即可。

## 一、快速开始

### 方式 1：本地直接打开（推荐先试这个）

```bash
双击 index.html          # 或用浏览器打开该文件
```

### 方式 2：部署到 GitHub Pages（免费）

```bash
git init && git add . && git commit -m "init"
git branch -M main && git remote add origin git@github.com:<你的账号>/<仓库名>.git
git push -u origin main
# 仓库 Settings → Pages → Source 选 main / (root) → Save
# 稍等 1~2 分钟，访问 https://<账号>.github.io/<仓库名>/
```

仓库根目录已放 `.nojekyll`，避免 GitHub 的 Jekyll 处理吞掉 `native/`、`js/` 等资源。

### 方式 3：起一个本地静态服务

```bash
python3 server.py --port 8000
# 浏览器打开 http://localhost:8000/
```

这只是把同一批静态文件以 http:// 方式送出去，用来规避 `file://` 下浏览器对
IndexedDB / WASM 的限制。**它不存数据、不做同步**，与 GitHub Pages 跑的是同一套代码。

## 二、首次进入：三步初始化

1. **站点保护密码**：所有人进入站点都要先输这道密码（≥4 位），输错进不去。
   注意它 ≠ 登录密码，是"整站的门禁"。
2. **站长账号**：昵称 + 登录密码（≥4 位），自动成为站长（owner）。
3. **成员注册**：见下面的「注册审核流程」——新人写一段申请说明，站长通过后才能登录。

### 注册审核流程（固定账户的核心）

```
新人填「昵称 + 申请说明 + 密码」提交
        ↓
   进入待审核队列，无法登录（登录会提示"请等待站长通过"）
        ↓
站长：管理面板 → 审核   看到昵称 + 申请说明 + 申请时间
        ↓
   通过（对方即可用原密码登录）  /  拒绝（删除该申请）
```

申请说明就是让申请人写一段话，例如"我是高二3班的李明，想进来讨论算法题"。
站长据此判断是不是认识的人。通过后全场会收到一条系统消息。

三种准入方式，在 **管理面板 → 站点** 里切换：

| 方式 | 设置 | 场景 |
| --- | --- | --- |
| 申请 + 审核（默认） | 开放注册 开 · 注册审核 开 | 想认识的人自己申请，你把关 |
| 免审核 | 开放注册 开 · 注册审核 关 | 完全开放，填完即用 |
| 仅手动开户 | 开放注册 关 | 最严格，只能你**用户 → ＋手动开户**，填昵称和初始密码 |

> 注意：这里**不是实名制**，不强制填真实姓名，也没有"真实姓名"字段。
> 唯一的把关材料就是申请人自己写的那段申请说明。

## 五、运行架构（本地与上线版完全一致）

**全项目只有一套架构**，不存在"本地模式 / 后端模式"的切换：

```
唯一数据源   浏览器内存中的 state 对象
持久化       localStorage（状态快照） + IndexedDB（图片/视频）
跨标签同步   BroadcastChannel 广播 + storage 事件
收敛策略     任何一份 state 进来都走同一套 merge（按 id 去重、按时间取新、删除不可逆）
媒体路径     一律压缩后写入 IndexedDB，消息只记 mediaId（无 URL、无外链）
```

下面三种打开方式跑的是**同一份、同一套代码路径**，功能与数据结构完全相同：

| 打开方式 | 说明 | 差异 |
| --- | --- | --- |
| 双击 `index.html`（`file://`） | 零依赖，最快 | 浏览器会限制 IndexedDB / WASM / fetch，媒体转内存、WASM 自动跳过 |
| `python3 server.py`（`http://`） | 自带运行环境，规避上述限制 | 无 |
| GitHub Pages（`https://`） | 上线版 | 无 |

> `file://` 下的差异是**浏览器能力降级**，不是代码分支——项目里没有任何
> `if (本地) ... else if (线上) ...` 的逻辑。`server.py` 只是静态文件服务器，
> 不存数据、不做同步，因此用它打开与部署到 Pages 是同一套运行架构。

### 多标签即多人（自测技巧）

同一浏览器开两个标签页，注册两个账号，即可实时私聊 / 建群 / 体验管理员权限。
这是 BroadcastChannel 同源广播的效果，本地与 Pages 都支持。

### 跨设备搬运数据

数据不出浏览器，换设备请用「管理面板 → 站点 → 导出 JSON / 导入 JSON」，
导入走的是与同步完全相同的 `merge` 逻辑，本地与上线版操作一致。

## 六、可选的 C++ / WASM 加速

`native/accel.cpp` 用 C++ 实现 SHA-256，用于加速密码哈希。**完全可选**，
加载失败会自动回退到纯 JS 实现，不影响任何功能。

```bash
# 原生编译自测（只要 g++）
g++ -O2 -std=c++17 native/accel.cpp -o accel && ./accel
# 应输出：SHA-256("abc") = ba7816bf8f01cfea414140de5dae2223b00361a396...

# 编译为 WASM（需要 emscripten）
emcc -O3 -std=c++17 native/accel.cpp -o native/accel.wasm \
     -sEXPORTED_FUNCTIONS=_sha256_hex,_accel_alloc,_accel_free,_accel_selftest \
     -sEXPORTED_RUNTIME_METHODS=ccall,cwrap -sINITIAL_MEMORY=65536 --no-entry
```

产物 `native/accel.wasm` 放好即可，`js/net.js` 会自动探测并启用，
`/env` 面板里能看到「WASM 加速：已启用」。

## 七、安全与隐私说明

- 密码一律 **加盐 + 4000 轮 SHA-256 迭代** 后存储，任何模式下都不明文落盘。
- 纯本地模式下数据不出浏览器；后端模式下仅在你主动配置后才会传输。
- 站点保护密码与登录密码相互独立，保护密码忘了可用「管理面板 → 站点」重置
  （需站长登录密码验证），或直接删掉浏览器站点数据重建。
- 这是面向熟人小圈子的轻量实现，不是企业级安全产品，**不要用于敏感信息传输**。
