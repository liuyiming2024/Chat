部署与数据

一、当前架构

全站是纯前端静态站点，部署在 GitHub Pages 免费版，网址：

https://liuyiming2024.github.io/Chat/
  • 零依赖：不引入任何第三方库、CDN、外部字体。
  • 无版权争议：Markdown 解析、LaTeX 渲染、SHA-256、媒体压缩、代码高亮均为独立手写实现，MIT 协议。
  • 本地与线上一致：不存在"本地模式 / 线上模式"的代码分支，三种打开方式跑的是同一份代码。

二、目录结构

index.html            首页
assets/site.css       整站共用样式
assets/site.js        整站共用脚本（主题、导航、后端配置）
chat/                 聊天室（index.html + css + js）
tieba/                贴吧
docs/                 使用手册（本页所在）
chat/supabase/        数据库建表脚本
.nojekyll             让 Pages 原样发布

三、数据存在哪里

内容存在哪换设备还能看到吗
聊天记录、账号、房间各人浏览器的 localStorage不能
图片、视频、语音各人浏览器的 IndexedDB不能
贴吧帖子数据库（配置后）能
重要：重新上传代码或回滚版本，清不掉各人浏览器里的数据。 数据按域名存储，不按路径，所以把聊天室从 /Chat/ 搬到 /Chat/chat/ 不会丢数据。要清空只能本人清浏览器站点数据，或站长用「管理面板 → 站点 → 重置站点」。

四、跨设备搬运聊天数据

管理面板 → 站点 → 导出 JSON，在另一台设备上 导入 JSON。 导入走的是与同步完全相同的合并逻辑（按 id 去重、按时间取新、删除不可逆）， 本地与上线版操作一致。

五、接数据库后端（可选）

想让聊天记录和贴吧跨设备可见，需要接数据库。脚本都已备好，步骤：

  1. 到数据库服务商创建项目，拿到 Project URL 和 publishable key。 只取 publishable，不要 secret key——后者权限极高，放进网页等于裸奔。
  2. 在 SQL Editor 里执行 chat/supabase/schema.sql（聊天室，8 表 + 33 个函数） 和 chat/supabase/forum.sql（贴吧，2 表 + 4 个函数）。
  3. 贴吧页面点「后端设置」填入 URL 和 key，立即生效，配置存在 localStorage。
免费项目的已知问题：连续 7 天没有数据库活动会被自动暂停， 全站返回 540，数据不会丢但需要手动恢复。 解决办法是配置定时保活（每 3 天请求一次数据库）。 注意保活脚本依赖仓库的定时任务，若仓库长期无提交，定时任务也可能被自动禁用。

六、本地运行

# 方式 1：直接双击（最快，但部分浏览器会限制 IndexedDB 与录音）
双击 chat/index.html

# 方式 2：起本地服务（推荐，功能完整）
python3 chat/server.py --port 8000
# 浏览器打开 http://localhost:8000/

server.py 只用 Python 标准库，只是把静态文件以 http 方式送出去， 不存数据、不做同步。

七、可选：C++ / WASM 加速

g++ -O2 -std=c++17 chat/native/accel.cpp -o accel && ./accel

用 C++ 实现 SHA-256 加速密码哈希。完全可选，加载失败会自动回退到纯 JS 实现， 不影响任何功能。

八、浏览器要求

Chrome / Edge / Firefox / Safari 近两年版本均可。 file:// 直接打开时部分浏览器会限制 IndexedDB 与录音， 此时媒体存内存、WASM 自动跳过，聊天功能照常。
